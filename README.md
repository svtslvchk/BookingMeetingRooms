# Система бронирования переговорных комнат

Backend-приложение для управления переговорными комнатами и их бронированиями.

Проект реализован на **FastAPI** с асинхронным взаимодействием с **PostgreSQL** через **SQLAlchemy 2.0**. Для управления изменениями структуры базы данных используется **Alembic**. Аутентификация пользователей реализована с использованием **JWT**.

## Возможности

* регистрация и аутентификация пользователей;
* JWT-аутентификация;
* управление профилем пользователя;
* создание и управление переговорными комнатами;
* создание бронирований;
* получение расписания переговорных комнат;
* получение списка бронирований пользователя;
* проверка пересечения временных интервалов при бронировании;
* валидация входных данных с помощью Pydantic;
* асинхронное взаимодействие с PostgreSQL;
* миграции базы данных с помощью Alembic;
* обработка исключений на уровне приложения;
* автоматизированное тестирование с использованием Pytest;
* веб-интерфейс на чистом JavaScript с использованием Fetch API.

## Архитектура

Приложение построено по принципу **трехслойной архитектуры (Layered Architecture)**:

```text
HTTP Request
     │
     ▼
┌─────────────────┐
│    API Routes   │
│   Controllers   │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│    Services     │
│ Business Logic  │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  Repositories   │
│  Data Access    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   PostgreSQL    │
└─────────────────┘
```

### API Routes

Отвечают за обработку HTTP-запросов, валидацию входных данных с помощью Pydantic-схем и вызов соответствующих сервисов.

### Services

Содержат бизнес-логику приложения.

В частности, здесь выполняется проверка пересечения временных интервалов при создании бронирования и реализуются основные бизнес-правила системы.

### Repositories

Инкапсулируют операции доступа к данным и взаимодействие с SQLAlchemy.

Такое разделение позволяет отделить бизнес-логику от деталей работы с базой данных.

Подробнее об архитектуре и модели данных:

**[→ ARCHITECTURE.md](ARCHITECTURE.md)**

## Модель данных

Основные сущности приложения:

* **User** — пользователь системы;
* **Room** — переговорная комната;
* **Booking** — бронирование комнаты на определённый временной интервал.

Для хранения данных используется **PostgreSQL**.

Для таблицы бронирований предусмотрен составной индекс по:

```text
(room_id, time_start, time_end)
```

## Аутентификация

Для авторизации используется **JWT (JSON Web Token)**.

Основной flow:

```text
Login
  │
  ▼
Проверка учетных данных
  │
  ▼
Создание access_token
  │
  ▼
Authorization: Bearer <token>
  │
  ▼
Проверка токена через FastAPI Depends
  │
  ▼
Получение текущего пользователя
```

Пароли пользователей хранятся в виде хэшей, а не в открытом виде.

Токен имеет ограниченное время жизни и передаётся клиентом в заголовке:

```http
Authorization: Bearer <token>
```

## Проверка пересечения бронирований

При создании бронирования система проверяет, не пересекается ли выбранный пользователем временной интервал с уже существующим бронированием той же переговорной комнаты.

Это позволяет предотвратить одновременное бронирование одной комнаты на пересекающиеся временные интервалы.

## Тестирование

Для автоматизированного тестирования используется **Pytest**.

Тесты запускаются с использованием отдельной тестовой базы данных, чтобы данные основной базы не изменялись во время выполнения тестов.

Запуск:

```bash
pytest -v
```

## Запуск проекта

### 1. Клонирование репозитория

```bash
git clone https://github.com/svtslvchk/BookingMeetingRooms.git
cd BookingMeetingRooms
```

### 2. Настройка переменных окружения

Создайте файл `.env` в корневой директории проекта.

Пример:

```env
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_secure_password
DB_NAME=booking_db

JWT_SECRET_KEY=your_secret_key
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
```

Секретный ключ JWT можно сгенерировать, например, командой:

```bash
openssl rand -hex 32
```

### 3. Установка зависимостей

Создайте виртуальное окружение:

```bash
python3 -m venv .venv
```

Активируйте его.

Linux / macOS / WSL:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установите зависимости:

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Применение миграций

После создания базы данных выполните:

```bash
alembic upgrade head
```

### 5. Запуск приложения

```bash
uvicorn app.main:app --reload
```

После запуска приложение доступно по адресу:

```text
http://127.0.0.1:8000/
```

## Веб-интерфейс

Проект также содержит лёгкий веб-интерфейс на чистом JavaScript.

Через интерфейс можно:

1. зарегистрировать пользователя;
2. выполнить вход;
3. получить JWT-токен;
4. создать переговорную комнату;
5. создать бронирование;
6. проверить работу системы бронирования.

Взаимодействие с backend выполняется через HTTP-запросы с использованием `Fetch API`.
